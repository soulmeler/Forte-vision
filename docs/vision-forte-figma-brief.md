# vision-forte — бриф для UI/UX в Figma

## 1. Что создаём

Внутренний инструмент ForteBank для проверки видеозаписей кассовых операций. Пользователь загружает видео, локальная модель ищет признаки возможных нарушений, а сотрудник проверяет результат по таймкодам, кадрам и нормативному основанию.

**Пользователи:** сотрудники контроля кассовых операций, проверяющие и руководители подразделений. Интерфейс должен помогать быстро разобраться в конкретной записи и принять решение.

**Формат:** веб-интерфейс на HTML/CSS/JS, позднее — запуск через Electron на ноутбуках. Сейчас проектируем интерфейс; сборка `.app` не нужна.

## 2. Основной сценарий

1. Открыть «Проверка видео».
2. Перетащить запись или нажать «Выбрать видео».
3. Увидеть имя файла, длительность, размер и видеоплеер.
4. Нажать «Проверить видео» и дождаться результата.
5. Получить один из двух ответов: «Нарушение не обнаружено» или «Обнаружены признаки возможных нарушений».
6. Выбрать событие, перейти к нужной секунде, рассмотреть кадры и прочитать обоснование.
7. При необходимости открыть нормативный источник или загрузить другую запись.

## 3. Структура интерфейса

### Sidebar — оставить

- Название **vision-forte**, подпись «Контроль кассовых операций».
- Основной раздел: «Проверка видео».
- Дополнительный раздел: «Подключение».
- Внизу: «Как это работает» и спокойная подпись о локальной обработке.

### Главный экран «Проверка видео»

- Короткий заголовок и одна строка пояснения.
- Статус режима: демонстрация или локальный сервис. Не показывать «Подключено» без проверки соединения.
- Слева: загрузка файла, затем видеоплеер, сведения о записи, замена файла и кнопка запуска.
- Справа: результат, список событий и подробности выбранного события.
- На узком экране результат располагается под видео. Сохранить доступ к навигации.

### Результат проверки

Для каждого события показать:

- Название предполагаемого нарушения и таймкод `мм:сс`.
- Короткое описание того, что видно, и почему это требует проверки.
- От одного до трёх кадров с временем; нажатие открывает крупный просмотр.
- Нормативное основание: название документа, пункт/раздел при наличии и ссылка.

Нажатие на событие переводит плеер к его таймкоду. Выбранное событие явно выделяется. Если основание не передано, показать «Нормативное основание не указано» — не придумывать ссылку.

При отсутствии событий показать ясный итог без пустых карточек. Рядом с результатами кратко пояснить: окончательное решение принимает проверяющий.

### Подключение и справка

- Настройки в модальном окне: демо / локальный сервис, адрес сервиса, API-ключ, сохранение, ошибки ввода.
- Демо явно обозначено: это пример интерфейса, загруженное видео не анализируется.
- Справка: три коротких шага — загрузить, запустить, проверить события.
- Увеличенный кадр: изображение, таймкод, описание и кнопка закрытия.

## 4. Состояния, которые нужно нарисовать

| Состояние | Что видит пользователь |
|---|---|
| Нет файла | Область загрузки, отключённая кнопка запуска, «Нет результатов» |
| Файл выбран | Плеер, сведения о файле, активная кнопка проверки |
| Обработка | Текущий этап, прошедшее время, индикатор без выдуманных процентов |
| Есть события | Вердикт, список событий, выбранное событие и доказательства |
| Нет событий | «Нарушение не обнаружено», возможность проверить другую запись |
| Ошибка | Понятная причина и следующее действие: повторить, заменить файл или открыть настройки |
| Демо | Явная отметка, что результат учебный |

Предусмотреть неподдерживаемый файл, превышение размера, недоступный сервис, неверный ключ, тайм-аут и недоступный предпросмотр. Ошибка обработки никогда не выглядит как отсутствие нарушения.

Кнопка «Остановить ожидание» прекращает ожидание ответа; она не должна обещать отмену серверной задачи.

## 5. Визуальное направление

- Основной цвет банка: **`#952650`**. Использовать для главных действий, активной навигации и выбранных элементов.
- Белые поверхности, светло-серый фон, тёмный читаемый текст, тонкие границы.
- Спокойный рабочий интерфейс: без градиентов, свечения, больших рекламных заголовков, декоративных иллюстраций и лишних карточек.
- Sidebar сохранить. Не добавлять графики, рейтинги сотрудников, KPI и проценты уверенности без реальных данных и задачи.
- Основной текст 14–16 px, понятные подписи, кнопки высотой около 40–44 px. Небольшие скругления, минимум теней.
- Цвет дополняется текстом или значком. Нужны видимый фокус клавиатуры, состояния hover / disabled / selected и читаемый контраст.
- Основной макет: ноутбук **1440 × 900**; проверить также **1280 × 800**. Загрузка и запуск должны быть легко доступны.
- Все пользовательские тексты — на русском. Название продукта — **vision-forte**.

## 6. Границы MVP и связь с моделью

**В MVP:** загрузка одной записи, локальный анализ, плеер, события, таймкоды, доказательства, нормативные основания, подключение сервиса и демо.

**Пока не нужны:** регистрация, роли, история, отчёты для руководства, пакетная загрузка, экспорт и уведомления.

Видео и модели обрабатываются локально. Для жюри предусмотрен отдельный доступ к API по ключу. UI загружает файл через `POST /api/v1/analyze`, получает `job_id` и запрашивает статус через `GET /api/v1/jobs/{job_id}`. Статусы: `processing`, `done`, `failed`; ожидание — до 5 минут. Технические маршруты не выводить на главный экран.

Обязательный формат кейса — `.mov`. Текущий интерфейс также принимает `.mp4` и `.webm`, до 300 МБ; поддержку реального анализа этих форматов нужно согласовать с backend.

## 7. Что получить в Figma

1. Главный экран во всех состояниях из таблицы.
2. Модальные окна подключения, справки и просмотра кадра.
3. Компоненты: sidebar, кнопки, поля, статус, карточка события, кадр, уведомление и индикатор обработки.
4. Общие стили цветов и текста, Auto Layout и правила изменения ширины.
5. Кликабельный прототип: загрузка → обработка → результат → событие → кадр.

Для макетов использовать синтетические заглушки с пометкой «Демо». Банковские видео, кадры и описания сцен не отправлять в облачные AI-инструменты: это ограничение кейса.
